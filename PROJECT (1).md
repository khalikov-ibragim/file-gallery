
# Simple Gallery — техническое задание для DevOps

> Легенда: команда разработки закончила фичу (загрузка и просмотр
> изображений) и передаёт её тебе как DevOps-инженеру. Ниже — архитектура,
> сервисы, порты, переменные окружения. Твоя задача — написать
> `Dockerfile`-ы и `docker-compose.yml`, которые всё это поднимут.

## 1. Что за проект

Простая галерея: пользователь загружает изображение через форму на сайте,
оно появляется в общей сетке. Можно удалить своё изображение. Никакой
авторизации нет — это учебный MVP.

- Backend: Node.js, Express (REST API).
- Frontend: статичные HTML/CSS/JS, без сборки.
- Метаданные файлов (имя, размер, дата): PostgreSQL.
- Сами файлы (байты изображений): MinIO — S3-совместимое объектное
  хранилище. Это НЕ база данных и не файловая система контейнера —
  отдельный сервис, специально созданный для хранения файлов/объектов,
  так же работают AWS S3 / Google Cloud Storage в проде.

## 2. Архитектура

```
                     ┌────────────┐
   браузер  ───────▶ │  frontend  │  статика (html/css/js)
      │              └────────────┘
      │ REST (upload / list / delete)
      ▼
┌────────────┐     ┌────────────┐     ┌────────────┐
│  backend   │────▶│  postgres  │     │   minio    │
│ (node.js)  │     │ (метаданные)│    │ (файлы)    │
└────────────┘     └────────────┘     └────────────┘
      │                                     ▲
      │  backend пишет файл в minio         │
      └─────────────────────────────────────┘
                                              ▲
   браузер ─────────────────────────────────┘
   (грузит картинки НАПРЯМУЮ из minio, в обход backend)
```

**Ключевой нюанс сети (важнее, чем в прошлом проекте):** backend
загружает файл в MinIO через внутреннюю docker-сеть — обращается к
контейнеру по его сервисному имени (например, `minio:9000`). Но когда
браузер потом отображает картинку (`<img src="...">`), он обращается к
MinIO **напрямую, в обход backend** — и делает это не из docker-сети, а
с хост-машины. Значит порт MinIO должен быть:
1. проброшен наружу (`ports:` в compose), и
2. backend должен формировать публичные ссылки на файлы с адресом,
   который реально доступен из браузера (не `minio:9000`, а
   `localhost:9000` или как ты его назовёшь) — см. переменную
   `MINIO_PUBLIC_URL` в `.env.example`, она специально отделена от
   `MINIO_HOST`/`MINIO_PORT`, которые backend использует для внутреннего
   подключения.

Если перепутать — картинки не будут отображаться в браузере (или будет
бесконечная загрузка), хотя сам upload на backend будет отрабатывать
без ошибок. Хороший повод потренироваться в отладке именно такого рода
проблем.

## 3. Сервисы и требования к контейнерам

| Сервис    | Образ / билд                  | Порт (внутр.) | Порт наружу (рекоменд.) | Persist? |
|-----------|---------------------------------|---------------|----------------------------|----------|
| frontend  | билдится из `./frontend`        | 80 (nginx)    | 8080                        | нет |
| backend   | билдится из `./backend`         | 4000          | 4000                        | нет (данные в postgres/minio) |
| postgres  | официальный образ `postgres`    | 5432          | не обязательно наружу       | да, volume |
| minio     | официальный образ `minio/minio` | 9000 (API), 9001 (консоль) | да, оба     | да, volume |

### backend

- Стартовая команда: `npm install && npm start` (образ на базе
  `node:20-alpine`).
- Слушает порт из `PORT` (по умолчанию 4000).
- При старте сам создаёт таблицу в Postgres и бакет в MinIO — есть
  retry-цикл на 15 попыток по 2 секунды, если postgres/minio ещё не
  готовы. Как и в прошлом проекте, правильная практика —
  `depends_on: condition: service_healthy`, а не полагаться на retry.
- Переменные окружения (см. `backend/.env.example`):
  - `PORT`
  - `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`
  - `MINIO_HOST`, `MINIO_PORT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET`
  - `MINIO_PUBLIC_URL` — отдельно от `MINIO_HOST`/`MINIO_PORT`, см. раздел 2
- Health-эндпоинт: `GET /health` → `{ "status": "ok" }`.
- REST API:
  - `GET /api/files` — список файлов
  - `POST /api/upload` — multipart-загрузка, поле `file`
  - `DELETE /api/files/:id` — удаление

### frontend

- Чистая статика: `index.html`, `style.css`, `app.js`.
- По умолчанию ходит на `http://localhost:4000`. Переопределяется через
  `window.GALLERY_API_URL`, если нужно.
- Раздавать через `nginx:alpine`, как и в прошлом проекте.

### postgres

- `postgres:16-alpine`, обязательно volume для
  `/var/lib/postgresql/data`.
- Переменные: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` —
  должны совпадать с `DB_USER`/`DB_PASSWORD`/`DB_NAME` у backend.

### minio

- Официальный образ `minio/minio`, команда запуска:
  `server /data --console-address ":9001"`.
- Два порта: `9000` — сам API (им пользуется backend и браузер),
  `9001` — веб-консоль администратора MinIO (удобно, чтобы визуально
  посмотреть на хранящиеся файлы, аналог pgAdmin, но для файлового
  хранилища).
- Переменные: `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` — должны
  совпадать с `MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` у backend.
- Обязательно volume для `/data`, иначе все загруженные файлы пропадут
  при пересоздании контейнера.

## 4. Локальный запуск без Docker (проверить, что код рабочий)

```bash
cd backend
cp .env.example .env
npm install
npm start   # http://localhost:4000

cd frontend
npx serve .  # либо просто открой index.html
```

Понадобятся локальные Postgres и MinIO — либо сразу переходи к Docker
Compose.

## 5. Твоя практика (DevOps-часть)

`Dockerfile` и `docker-compose.yml` намеренно отсутствуют — собери сам.

1. [ ] `backend/Dockerfile` на `node:20-alpine`.
2. [ ] Раздача `frontend` через `nginx:alpine`.
3. [ ] `docker-compose.yml` с 4 сервисами: `frontend`, `backend`,
       `postgres`, `minio`.
4. [ ] Переменные окружения — из `backend/.env.example`, включая
       правильную настройку `MINIO_PUBLIC_URL` (см. раздел 2 — это
       главная ловушка проекта).
5. [ ] Volume для `postgres` и отдельный volume для `minio` (`/data`).
6. [ ] `depends_on` так, чтобы backend стартовал после postgres и minio.
7. [ ] Проверка снаружи (визуально, не только через консоль):
   - [ ] `http://localhost:8080` открывает галерею в браузере;
   - [ ] можно загрузить картинку через форму, она появляется в сетке;
   - [ ] картинка реально отображается (не битая иконка) — это и есть
         проверка того, что `MINIO_PUBLIC_URL` настроен верно;
   - [ ] `http://localhost:9001` открывает консоль MinIO, там виден
         бакет `gallery` и загруженные файлы внутри;
   - [ ] кнопка "удалить" в галерее реально убирает файл и из
         интерфейса, и из бакета в консоли MinIO.
8. [ ] Проверь, что после `docker compose down && docker compose up`
       (без `-v`) все файлы и записи в галерее сохраняются.

### Задания со звёздочкой

- Настроить healthcheck для postgres и minio, использовать
  `condition: service_healthy` вместо retry-цикла в коде.
- Добавить `pgadmin` сервисом, как в прошлом проекте — сравнить, чем
  визуальный осмотр в pgAdmin (таблица `files`) отличается от того, что
  видно в консоли MinIO (сами файлы) — это разные хранилища одного и
  того же приложения.
- Ограничить MinIO API-порт (`9000`) так, чтобы наружу торчала только
  консоль, а сами файлы отдавались через backend (presigned URL) —
  безопаснее, чем публичный бакет, который используется в этом MVP.
